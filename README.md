# 角色卡 · dsh-role-card

> 在 DeepSeek Harness 的侧边栏里粘一张角色卡，保存即进入角色；切换角色、退出角色都只要一次点击。

一个纯本地运行的 DSH 侧边栏插件：角色设定、对话历史、小说章节全部躺在你自己机器的 `~/.dsh/dsh-role-card/` 里，不经过任何第三方服务器。角色的每一句话都由你本机 Harness 已经配置好的模型路由直连生成。

## 特性

| | 特性 | 说明 |
|---|---|---|
| 🗂️ | **侧栏常驻** | 注册在 `sidebar.panellist` 与 `main` 两个 slot 上，跟别的会话互不干扰——角色只在这块面板里说话 |
| 📋 | **粘卡即演** | 整张角色卡粘进编辑框，正文上限 400KB，最多 200 张卡 |
| 🔗 | **链接导入** | 角色卡站页面、PNG 酒馆卡直链、Next.js 站点、JSON-LD、OpenGraph 都能识别 |
| ✨ | **AI 扩写** | 一句设定或一段简介，扩成能直接开演的完整卡；提示词可外置替换 |
| 📖 | **小说逐章** | 抓整本小说分章入库，每轮只注入当前章，面板点「下一章」推进 |
| 🎛️ | **逐卡调参** | 内容模式（成人/普通）、尺度五档（无/暗示/含情/露骨/极致）、节奏三档（慢热/自然/直接）、文风五种（角色扮演/小说体/聊天体/剧本体/日记体）、年龄（成年/原文）全都可以逐卡切，切换立即生效 |
| 🤖 | **直连模型** | v1.3 起直接走 `ctx.llm.stream`，不建 Agent、不写会话文件、不碰全局提示词 |
| 📱 | **手机访问** | 同一 WiFi 下开一个带口令的局域网反代，扫码即用 |
| 🔒 | **纯本地** | 无遥测、无云端、无外部请求（除了你自己触发的抓取） |

## 安装

### 前置

- DeepSeek Harness 桌面端（`dsh`），一个可用的 profile（默认 `desktop`）
- Node.js ≥ 20.11（Harness 自带，通常不用单独装）
- 一个能正常对话的模型路由（角色扮演默认优先 `deepseek-v4-pro`，不可用时自动回退）

### 方式一：从 GitHub 安装（推荐给用户）

1. 打开你要装进去的 profile 目录，例如 `~/.dsh/profiles/desktop/`（Windows：`C:\Users\<你>\.dsh\profiles\desktop`）。
2. 编辑该目录的 `package.json`，在 `dependencies` 里加一行：

   ```json
   "dsh-role-card": "github:yugege123/dsh-role-card"
   ```

   想钉版本就写 `github:yugege123/dsh-role-card#v1.8.0`。

3. 同一份 `package.json` 的 `dsh.profile.bundles` 数组里加上包名：

   ```json
   "bundles": [
     "@deepseek-ai/dsh-base",
     "...",
     "dsh-role-card"
   ]
   ```

4. 在该 profile 目录里装依赖：

   ```bash
   pnpm install
   ```

5. 重启 Harness 桌面端。侧栏出现「角色卡」即安装成功。

### 方式二：从本地目录安装（推荐给开发者）

把仓库克隆或复制到任意目录（路径里不要有中文和空格更稳），然后把 `dependencies` 写成 link 指向它：

```json
"dsh-role-card": "link:D:/path/to/dsh-role-card"
```

其余步骤同上（`bundles` 加包名 → `pnpm install` → 重启）。改动源码后只要重启宿主（客户端改动刷新页面即可）就生效，不需要重新安装。

### 卸载

从 `dsh.profile.bundles` 里删掉 `dsh-role-card`，再从 `dependencies` 删掉那一行，`pnpm install`，重启。数据目录 `~/.dsh/dsh-role-card/` 会保留，想彻底清掉就手动删。

## 装到手机（DSHM）

手机上的 dsh 宿主一样能装它。以 [DSHM](https://github.com/RochelimitDawn/DSHM)（安卓 APK，内置 Debian 12 子系统 + dsh CLI，Web UI 在 `127.0.0.1:3080`）为例，最省事的是本地 tgz：

```bash
# 电脑上，插件目录里
npm pack                       # → dsh-role-card-1.8.1.tgz
python -m http.server 8000     # 同 WiFi 下给手机取件
```

```bash
# 手机 DSHM 的终端里
cd ~ && curl -O http://PC_IP:8000/dsh-role-card-1.8.1.tgz
dsh plugin --profile web add ./dsh-role-card-1.8.1.tgz
# 然后重启 Web 服务 → 127.0.0.1:3080 → 左侧栏「角色卡」
```

私有仓库要走带凭据的 git URL（`https://<user>:<token>@github.com/...#v1.8.1`），改源码则用 `link:` 软链。三种方式的完整流程、验证命令、故障对照表在 **[docs/MOBILE.md](docs/MOBILE.md)**。

## 快速上手

1. 侧栏点开「角色卡」——空面板上写着「还没有角色卡」。
2. 两种建卡方式，选一个：
   - **粘链接**：把角色卡站点的角色页链接或 PNG 酒馆卡直链粘进导入框，点「导入」；
   - **手写**：点「新建角色卡」，把设定、性格、场景、开场白、对话示例整段粘进去，点「保存」。
3. 卡片出现在列表里，点「进入角色」（或第一次点「开场」让角色先说话）。
4. 在底部输入框说点什么，`Enter` 发送，`Shift+Enter` 换行。
5. 想切模式/尺度/节奏/文风/年龄，在对话页顶部的工具条上选，切换即生效；想换卡点「角色列表」，想彻底结束点「退出角色」。

## 界面与操作

### 列表页

- 每张卡显示名字、正文字数、正文前 160 字预览，以及小说卡当前章/总章数。
- 按钮：**开场**（空对话时让角色先说话）/ **进入角色** / **继续对话** / **编辑** / **删除**（删除需要连点两次确认）。
- 顶部：**新建角色卡**、**刷新**。

### 编辑页

- 「角色名（留空会自动从正文里取）」——留空时从正文里第一个 `# 标题` 或首行推断。
- 正文框支持 markdown，粘进来的酒馆卡原样保存，不做格式清洗。
- **AI 扩写**：把当前正文当素材再扩一遍（会覆盖正文，注意先保存）。
- **保存** / **取消**。

### 对话页

工具条从左到右：

| 控件 | 作用 |
|---|---|
| 模式：成人 / 普通 | 内容模式。见[模式与尺度](#模式与尺度) |
| 尺度：无 / 暗示 / 含情 / 露骨 / 极致 | 五档尺度，普通模式下锁定不可选 |
| 节奏：慢热 / 自然 / 直接 | 每一轮推进多少 |
| 文风：角色扮演 / 小说体 / 聊天体 / 剧本体 / 日记体 | 输出格式 |
| 字号：自动 / 小 / 中 / 大 | 对话字号，记在 `localStorage`（`drc-font-step`），手机上自动降一档 |
| 年龄：原文 / 成年 | 见[年龄模式](#年龄模式) |
| 下一章（n/m） | 小说卡专用，把章节指针往后推一章 |
| 继续导入 40 章（n/全书） | 小说卡专用，从已抓到的章往后补抓一批；抓完变「检查更新」 |
| 检查更新（n 章） | 问站点这本追到第几章了，有更新就提示你 |
| 角色列表 | 回到列表页（不退出角色） |
| 清空对话 | 把当前卡的历史归档（文件名加 `.deleted-<时间戳>`），面板清空 |
| 编辑角色 | 直接改这张卡 |
| 让角色开场 | 仅在空对话时可用，让角色先开口 |
| 发送 | 提交输入框内容 |

窄屏下这些动作会收进「⋯」菜单。

## 角色卡格式

角色卡就是一段 markdown 正文，没有必填字段——但写得越像「可以直接开演的资料」，演出来越稳。推荐结构（完整示例见 [`examples/card-sample.md`](examples/card-sample.md)）：

```markdown
# 角色名
> 来源：来源链接或「用户设定」

## 角色简介
身份、年龄、外形、当下处境，一到两段。

## 性格与说话方式
性格底色、忌讳、软肋；再给 2-3 句原声台词样本，把口癖和标点习惯写出来。

## 关系与背景
她与我、与其他关键人物的关系；造成眼下局面的关键事件，按时间写。

## 当前场景
这场戏在哪、她正在做什么、为什么现在就会发生。

## 可玩的钩子
三条不同的切入点或矛盾点，让对话能往三个方向走。

## 设定沿用提示
必须守住什么 / 什么可以随剧情变 / 什么不要碰。
```

要点：

- **具体动作比形容词有用**。「她习惯把袖子卷到小臂中间」比「她很随意」有用得多。
- **台词样本决定口吻**。写 2-3 句她真的会说的话，比写「说话温柔」有效。
- **开场白不必写死**。面板的「开场」会让模型自己按当前场景开口；想固定开场就把开场白单独写成一节。
- 正文上限 **400KB**——正常角色卡都在 5-30KB。

格式细节、字段含义与限制见 [`docs/CARD-FORMAT.md`](docs/CARD-FORMAT.md)。

## 链接导入

导入框粘一个 URL，插件按下面顺序尝试识别：

1. **PNG 酒馆卡**（SillyTavern Character Card V1/V2）：读 PNG 的 `tEXt` / `zTXt` / `iTXt` 块里的 `chara` 或 `ccv3`，base64 解码后解压成 JSON，取 `name` / `description` / `personality` / `scenario` / `first_mes` / `mes_example`。
2. **RSC payload**：页面里带 `characterData:{...}` 的 Next.js App Router 站点（dzmm、huoacg 一类）。
3. **通用 HTML**：`__NEXT_DATA__` → JSON-LD → OpenGraph 标题与描述，取最像角色简介的那一段。

抓取预算：单请求超时 25s、最多 4 次重试（退避 700ms）、单页上限 4MB、带常见桌面 UA。遇到反爬会给出明确文案（例如「连接被重置（站点反爬或代理线路不稳）」），不会静默失败。

小说链接走另一条路径，见下一节。

## AI 扩写

把素材粘进输入框、写好要求，点「AI 扩写」：

- 素材可以是角色站简介、小说片段、一句设定；超过 24000 字的部分会截断。
- 要写「想让她是什么身份、口吻、关系、剧情走向」就填在下面的要求框里，会优先满足。
- 输出是一张完整的卡（`# 角色名` + 角色简介 / 性格与说话方式 / 关系与背景 / 当前场景 / 可玩的钩子 / 设定沿用提示），至少 1200 字。
- 默认「只出草稿」，可以在回来的正文上直接改，再点保存。

提示词默认内置，可以外置覆盖——改文件不用重启宿主，每次请求现读：

```bash
# 默认位置
~/.dsh/dsh-role-card/expand-prompt.md
# 或者用环境变量指到别处
DSH_ROLE_CARD_EXPAND_PROMPT=/path/to/expand-prompt.md
```

一份可直接用的扩写提示词见 [`examples/expand-prompt.md`](examples/expand-prompt.md)。

## 小说逐章

点「小说导入」并粘一个小说目录页或章节页链接，先在「小说范围」里选一种：

| 范围 | 行为 |
|---|---|
| **快速（前 40 章）**（默认） | 只抓前 40 章，几秒就出卡；后面的章节进对话界面点「继续导入 40 章」一批批补 |
| **全部（整本，后台补更）** | 同样先抓前 40 章立刻出卡，剩下的交给插件进程里的后台任务分批抓（每批 100 章），进度在面板上自己涨，不用守着 |

抓取流程：

1. 抓目录页，解析章节链接（最多看 12 个候选入口页来定位真正的目录）；
2. 以 6 路并发抓章节，单章上限 40000 字，整本上限 200 万字；
3. 生成一张「原著 · 逐章」角色卡：卡正文含原著信息、章节索引与开篇 1800 字；
4. 之后**每一轮**只把当前章原文（最多 9000 字）注入提示词，并标注「第 N 章 / 共 M 章」。

长篇小说不会把上下文撑爆。面板上的「下一章（n/m）」推进指针；同一个链接重复导入会复用原来的卡并保留当前进度。

### 续导与追更

- **继续导入 40 章**：从已经抓到的最大章号往后抓 40 章（`EXTEND_BATCH_CHAPTERS`），抓过的章不重抓，新章按章号并进已有章表；卡片正文里的章节索引会跟着重写。
- **检查更新**：书追到最新章节后，按钮变成「检查更新」，点一下问站点这本现在一共多少章——有更新会告诉你「还有 N 章没抓」，再点「继续导入」补齐。
- 「全部导入」的后台任务还在跑时，手动续导会被跳过（提示「后台正在导入（n/m），等它跑完就行」），避免两路同时改同一份章表。
- 站点偶尔有一两章抓不到时，那一章的章号会留空，不会把后面的章挤位；续导结果里会带 `failedCount` 与失败章号列表。

章节原文、标题、作者、全书章数与已抓章数存在 `~/.dsh/dsh-role-card/novels/<cardId>.json`。

## 模型与路由

- 插件不硬编码 key，也不读配置文件里的密钥：它从当前进程里**已经跑通的 root agent** 复制 `provider + model`（桌面登录态的 `*account*` 路由优先），这样签发和传输一定可用。
- 角色扮演默认模型是 `deepseek-v4-pro`；如果这个模型在当前路由上不可用（返回空内容或抛错），自动回退到基础模型，日志里会留一行 `[dsh-role-card] empty answer from … - retrying …`。
- 卡片级覆盖：`POST /model {id, model}` 可以给单张卡指定模型，`model: null` 表示跟随自动路由。
- 采样参数：`temperature` 按尺度取——极致 `1.1`、露骨 `1.02`、其余 `0.9`；`maxTokens` 按文风取——聊天体 2200、角色扮演 1600、其余 4000。
- 同一张卡的对话是串行的：上一条还没回来时再发会被拒绝（「角色正在回应上一条，稍等」）。

诊断用：`GET /api/dsh-role-card/route` 返回当前选中的路由、候选路由列表、是否走直连。

## 面板不显示时

装上了、宿主也起来了，但侧边栏看不到「角色卡」，先看诊断端点：

```bash
curl -s -H 'x-dsh-role-card: ui' http://127.0.0.1:3080/api/dsh-role-card/diag
```

（桌面端端口看宿主输出，手机 DSHM 默认 `3080`。）

- `client` 为 `null` → 浏览器半从没跑到 `apply()`：插件本体没进 boot roster。确认 `package.json` 里 `dsh.bundle.patch` 与 `dsh.client` 都在、`cordis.patch.yml` 里有这一行，然后**完整重启宿主**（不是刷新页面）。
- `client.source` 为 `client-ready` → 已加载、已注册 slot，只是没显示：窄屏先展开侧栏抽屉；宽屏看 `sidebar.panellist` 有没有被别的插件占位。
- `client.source` 为 `client-error` → 面板内部抛错，读 `client.error` 原文。

## 模式与尺度

每张卡有四个独立旋钮，都存在卡上（跟着卡走，换设备也一样），改动立刻对下一轮生效。

### 内容模式（`mode`）

| 模式 | 值 | 行为 |
|---|---|---|
| **成人**（默认） | `adult` | 按尺度档写，五档任选 |
| **普通** | `normal` | **硬闸门**：完全不写性内容——没有性行为、没有性暗示式挑逗、没有裸露；也不用省略号/场景切换去暗示它发生过。尺度自动降到「无」（只有手动选「暗示」时保留暗示档） |

导入普通小说、普通角色卡时选「普通」，就不会往情色方向跑。

### 尺度（`tone`）

| 档 | 值 | 写到哪 | 篇幅 |
|---|---|---|---|
| 无 | `none` | 不落到具体性行为 | 300-700 字 |
| 暗示 | `hint` | 调情、目光、衣料摩擦，写到就停，张力靠留白 | 400-800 字 |
| 含情 | `soft` | 亲吻抚摸可以写到位，真正进入时用场景收束 | 400-900 字 |
| 露骨 | `explicit` | 动作/感官/反应/对话四层交织推进，不省略、不淡出 | 700-1200 字 |
| 极致 | `hard` | 直白的脏话与生理描写，每轮实质推进，允许支配/服从与轻微粗暴 | 700-1200 字 |

### 节奏（`pace`）

| 档 | 值 | 行为 |
|---|---|---|
| 慢热 | `slow` | 慢慢铺垫，不急着进入下一步 |
| 自然 | `steady` | 每轮必须往前走一步，不许「先转过去」「停一下」这类延期 |
| 直接 | `direct`（默认） | 当场完成，上一轮到哪这一轮必须再往前一步，并写出动作完成后的状态 |

节奏只在「成人模式 + 尺度不为无」时注入——普通模式和「无」档不需要推进节奏。

### 文风（`style`）

| 文风 | 值 | 输出形态 |
|---|---|---|
| 角色扮演 | `rp` | 单人视角，只演角色自己，禁止替用户叙述，400-800 字 |
| 小说体 | `novel`（默认） | 小说叙述，`*…*` 标动作，台词加引号，可与用户合写「我」，500-900 字 |
| 聊天体 | `chat` | 多条即时消息（`【她：…】`），短口语、错字撤回，8-20 条 |
| 剧本体 | `script` | 场景标题 + `【角色名：台词】` + 括号动作，400-900 字 |
| 日记体 | `diary` | 第一人称日记/独白，开头带时间戳，句子可断可划掉重写，400-900 字 |

提示词层面的完整契约（每一档的确切措辞、四条通用规则、注入顺序）见 [`docs/PROMPT-CONTRACT.md`](docs/PROMPT-CONTRACT.md)。

## 年龄模式

角色卡和原著里常写着「15 岁」「高中生」这类标注，模型会拿它当拒绝理由。插件给了两个开关：

| 模式 | 行为 |
|---|---|
| **成年**（默认，`adult`） | 只把**喂给模型的这一份提示词**里的小年龄写法成年化：`15 岁`→`24 岁`、`初中生/高中生`→`大学生`、`未成年`→`成年人`、`少年`→`年轻男人`、`小女孩/小男孩/小姑娘`→`姑娘`，并在设定区注明「原文若写了偏小的年龄，扮演中一律按成年人算」。**存档原文一字不改。** |
| **原文**（`original`） | 跳过成年化，让模型照原文的年龄、辈分演。 |

成年化的实现是纯文本替换（`adultizeForPrompt`），只处理明确的小年龄写法，其余文字原样保留；中文数字（十五岁）也认。完整规则见 [`docs/PROMPT-CONTRACT.md`](docs/PROMPT-CONTRACT.md)。

## 手机访问

面板里的「手机访问」块：

1. 点「开启」——在 `0.0.0.0` 上起一个局域网反代，转给本机 web 端口（HTTP 与 WebSocket 都转，所以对话流式输出正常）。
2. 手机和电脑连**同一个 WiFi**，扫二维码或点「复制链接」在手机浏览器打开。
3. 首次打开要输口令（口令页只有一个输入框），输对后写 30 天 cookie，之后免输。
4. 「换口令」会把所有已连的手机踢下线；「关闭」停止监听。

注意点：

- **只在面板开启期间监听**，关掉即停，不会后台常驻。
- 口令与端口会写进 `~/.dsh/dsh-role-card/lan.json`，所以重启宿主后手机书签仍然有效；点「换口令」会作废旧口令并踢掉所有已连设备。这个文件是本机明文，路径可用 `DSH_ROLE_CARD_LAN_STATE` 覆盖。
- 这是明文 HTTP，只适合可信的家庭/办公局域网；**不要在公共 WiFi 上开**——同网段的抓包者能读到你和角色的全部对话。
- 端口被占用时会自动往后顺延（最多试 10 个），再不行就交给系统分配。

细节见 [`docs/LAN.md`](docs/LAN.md)。

## 数据存放

全部在 `$DSH_HOME`（默认 `~/.dsh`）下，跟 profile 分离，重装插件不丢数据：

```
~/.dsh/dsh-role-card/
├── state.json            # 所有角色卡（正文在内），version:1
├── lan.json              # 手机访问的口令与端口
├── expand-prompt.md      # 可选：外置扩写提示词
├── chat/
│   └── <cardId>.json     # 每张卡的对话历史，最近 300 条
└── novels/
    └── <cardId>.json     # 小说分章原文与当前章节指针
```

写盘策略：单张卡的写入是串行的（`tmp` + `rename`），避免 Windows 上两个回合同时落盘报 `EPERM`。「清空对话」不是删除，是把文件重命名成 `<cardId>.json.deleted-<时间戳>`，随时可以捞回来。数据结构见 [`examples/state.schema.json`](examples/state.schema.json)。

## 配置项

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `DSH_HOME` | `~/.dsh` | 数据根目录，插件用 `<DSH_HOME>/dsh-role-card/` |
| `DSH_ROLE_CARD_NOVEL_DIR` | `<DSH_HOME>/dsh-role-card/novels` | 小说分章文件目录 |
| `DSH_ROLE_CARD_EXPAND_PROMPT` | `<DSH_HOME>/dsh-role-card/expand-prompt.md` | 扩写提示词文件路径 |
| `DSH_ROLE_CARD_LAN_STATE` | `~/.dsh/dsh-role-card/lan.json` | 手机访问口令与端口的落盘位置 |

代码里的固定上限（改要动源码）：正文 400KB / 卡 200 张 / 单条输入 8KB / 历史 300 条 / 请求体 400KB+64KB / 小说注入 9000 字 / 快速导入首批 40 章 / 每次续导 40 章 / 后台补更每批 100 章（批间停 400ms）。

## HTTP 接口

宿主半按 prefix 注册在 `/api/dsh-role-card` 下，全部要求请求头 `x-dsh-role-card: <每次启动随机生成的 token>`（或 `ui`），否则 403。token 通过注入到页面的 `window.__DSH_ROLE_CARD__.token` 拿到，所以**同源页面 + 自定义头**两道门槛挡掉了跨站调用。

常用几个：

```bash
# 状态快照（卡片列表 + 当前角色）
curl -s -H "x-dsh-role-card: ui" http://127.0.0.1:<webPort>/api/dsh-role-card/state

# 新建/覆盖一张卡
curl -s -X POST -H "x-dsh-role-card: ui" -H "content-type: application/json" \
  -d '{"name":"沈砚","body":"# 沈砚\n..."}' \
  http://127.0.0.1:<webPort>/api/dsh-role-card/save

# 说一句
curl -s -X POST -H "x-dsh-role-card: ui" -H "content-type: application/json" \
  -d '{"id":"<cardId>","text":"你回来了。"}' \
  http://127.0.0.1:<webPort>/api/dsh-role-card/chat
```

完整端点表（含 `/import` `/expand` `/novel` `/novel/extend` `/novel/next` `/lan` `/mode` `/tone` `/model` `/style` `/pace` `/agemode` 的入参与返回）见 [`docs/API.md`](docs/API.md)。

## 隐私与安全

- **不联网**：插件本身不向任何服务器发请求；唯一的对外流量是你主动点「导入 / 扩写 / 小说导入」时对目标站点的抓取，以及模型调用（走本机 Harness 已配好的路由）。
- **无遥测**：没有统计、没有上报、没有版本检查。客户端异常只写进本机宿主日志。
- **数据只在本地**：角色卡、对话、小说都在 `~/.dsh` 下，删目录即彻底清除。
- **鉴权**：所有接口要自定义头 token，跨站请求会被 preflight 挡掉；手机入口另有独立口令 + timing-safe 比较。
- **内容**：这是本地角色扮演工具，扮演内容由模型根据你提供的卡生成，属于虚构文本。你自己对导入和生成的内容负责——别把别人的付费内容、真实个人信息或你不该持有的东西塞进来再传出去。

发现安全问题请按 [`SECURITY.md`](SECURITY.md) 的流程私下报告。

### 发版流程

代码已经推在 <https://github.com/yugege123/dsh-role-card>，日常提交：

```bash
git add -A
git commit -m "fix: 一句话说清改了什么"
git push
```

打 tag 发版时按顺序做四件事：

1. 改 `package.json` 的 `version` 与 `client.js` 的 `VERSION`（两处必须一致，check 会拦）；
2. 在 [`CHANGELOG.md`](CHANGELOG.md) 顶部补一段（`## [x.y.z] — 日期` + 变更条目）；
3. `npm run check` 全过（语法 / 导出 / 版本一致性 / 四组旋钮行为 / 纯净性）；
4. `git tag v1.8.0 && git push --tags`，然后在 GitHub 上把 tag 发成 Release。

推送前确认这三件事，`.gitignore` 已经挡住了对应的坑：

- `state.json` / `chat/` / `novels/` / `lan.json` **不在**提交里（这些是你的私密数据，物理上也不在这个目录）；
- 源码目录里那堆 `.bak-*` 开发副本没有被带进来；
- `npm run check` 的「纯净性」一节全过（无本机路径、无邮箱、无密钥、无备份文件）。

## 已知限制

- 依赖 DSH 宿主提供的 `ctx.llm` / `slots` / API 前缀路由能力；宿主大版本变了可能要对齐接口。
- 小说抓取只认「目录页链接 + 正则找章节」的常见结构，遇到 JS 动态渲染或需要登录的站点会失败（会给明确错误文案）。
- 「清空对话」是归档不是销毁；文件会一直堆在 `chat/` 下。
- 手机访问是明文 HTTP + 单口令，没有 HTTPS，也没有多用户。
- 同一个角色只有一条对话线，不支持分支/多存档（想要分支可以复制一张卡）。
